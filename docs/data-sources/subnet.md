# fptcloud_subnet (Data Source)

Use this data source to read the subnets of a VPC, for example to place an instance in a subnet
that was created in the FPT Cloud console or by another Terraform configuration. It returns the
list `subnets`, which you can narrow down with `filter` blocks and order with `sort` blocks.

To create and manage a subnet, use the [`fptcloud_subnet`](../resources/subnet) resource. To learn
more, see [Subnets](https://docs.fptcloud.com/docs/fpt-network/subnets/overview/) in the FPT Cloud
documentation.

## Example Usage

All examples look up the VPC by name with the [`fptcloud_vpc`](vpc) data source:

```terraform
data "fptcloud_vpc" "example" {
  name = "example-vpc"
}
```

### Look up a subnet by name

Use this to get the ID of one existing subnet. `one()` returns the single matching subnet, and fails
if the filter matches more than one subnet.

```terraform
data "fptcloud_subnet" "app" {
  vpc_id = data.fptcloud_vpc.example.id

  filter {
    key    = "name"
    values = ["app-subnet"]
  }
}

output "app_subnet_id" {
  value = one(data.fptcloud_subnet.app.subnets).id
}
```

### Place an instance in an existing subnet

Use this when the subnet is managed outside your configuration. Pass the subnet `id` to the
`subnet_id` argument of [`fptcloud_instance`](../resources/instance).

```terraform
data "fptcloud_subnet" "app" {
  vpc_id = data.fptcloud_vpc.example.id

  filter {
    key    = "name"
    values = ["app-subnet"]
  }
}

variable "ssh_public_key" {
  type = string
}

variable "storage_policy_id" {
  type = string
}

resource "fptcloud_instance" "app" {
  vpc_id            = data.fptcloud_vpc.example.id
  name              = "app-server-01"
  image_name        = "Ubuntu-22.04" # Use an image name listed in your VPC
  flavor_name       = "2C4G"         # Use a flavor name listed in your VPC
  subnet_id         = data.fptcloud_subnet.app.subnets[0].id
  storage_size_gb   = 40
  storage_policy_id = var.storage_policy_id
  ssh_key           = var.ssh_public_key
  status            = "POWERED_ON"
}
```

### List several subnets, sorted by name

Use this to collect a group of subnets, for example every subnet whose name starts with `web-`.
`match_by = "re"` treats each value as a regular expression.

```terraform
data "fptcloud_subnet" "web" {
  vpc_id = data.fptcloud_vpc.example.id

  filter {
    key      = "name"
    values   = ["^web-"]
    match_by = "re"
  }

  sort {
    key       = "name"
    direction = "asc"
  }
}

output "web_subnet_ids" {
  value = [for subnet in data.fptcloud_subnet.web.subnets : subnet.id]
}
```

## Argument Reference

The following arguments are supported:

* `vpc_id` - (Required) The ID of the VPC whose subnets you want to read. Use the `id` of the
  [`fptcloud_vpc`](vpc) data source.
* `is_networks_iaas` - (Optional) Set to `true` to also return the `network_iaas_id` of each
  subnet. Defaults to `false`.
* `filter` - (Optional) One or more `filter` blocks as defined below. A subnet is returned only if
  it matches every `filter` block.
* `sort` - (Optional) One or more `sort` blocks as defined below. Blocks are applied in order.

### filter

* `key` - (Required) The subnet attribute to filter on. Valid values are `id`, `name`,
  `network_id`, `network_iaas_id`, `network_name`, `gateway` and `created_at`.
* `values` - (Required) A list of values. A subnet matches when its attribute matches at least one
  of the values (or all of them, see `all`).
* `match_by` - (Optional) How to compare the values. Valid values are `exact` (whole value,
  case-insensitive), `substring` (the value is contained in the attribute, case-sensitive) and `re`
  (the value is a regular expression). Defaults to `exact`.
* `all` - (Optional) Set to `true` to require the attribute to match all of the `values` instead of
  at least one. Defaults to `false`.

### sort

* `key` - (Required) The subnet attribute to sort on. Valid values are `id`, `name`, `network_id`,
  `network_iaas_id`, `network_name`, `gateway` and `created_at`.
* `direction` - (Optional) The sort direction. Valid values are `asc` and `desc`. When omitted, the
  subnets are sorted in ascending order.

## Attribute Reference

In addition to all arguments above, the following attributes are exported:

* `id` - An identifier generated by Terraform for this lookup. It is not a subnet ID.
* `subnets` - The list of subnets that match all `filter` blocks, in the order set by `sort`. Each
  element has the following attributes:
  * `id` - The ID of the subnet. Pass it to the `subnet_id` argument of
    [`fptcloud_instance`](../resources/instance) and other resources.
  * `name` - The name of the subnet.
  * `network_id` - The network ID of the subnet, as used by some other FPT Cloud services.
  * `network_iaas_id` - The infrastructure network ID of the subnet. Set
    `is_networks_iaas = true` to get this value.
  * `network_name` - The network name of the subnet, as FPT Cloud reports it.
  * `gateway` - The gateway address of the subnet.
  * `edge_gateway` - A map describing the edge gateway the subnet is connected to, with the keys
    `id`, `name` and `edge_gateway_id`.
  * `created_at` - The time the subnet was created.
  * `tag_ids` - The IDs of the tags attached to the subnet.

The CIDR, type and DNS servers of a subnet are not returned by this data source.

## Results and errors

* If no subnet matches your filters, `subnets` is an empty list and Terraform does not report an
  error. An expression such as `subnets[0].id` then fails. Use `one(...)` or check
  `length(data.fptcloud_subnet.app.subnets)` if the subnet may be missing.
* If the VPC has no subnets at all, the data source fails with an error.
