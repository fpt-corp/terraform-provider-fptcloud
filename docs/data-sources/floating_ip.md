# fptcloud_floating_ip (Data Source)

Use this data source to read the floating IPs (public IP addresses) allocated in a VPC. Typical
uses are finding the ID of a floating IP that was allocated in the FPT Cloud console, so that you
can associate it with an instance, or listing the addresses that are still free. It returns the list
`floating_ips`, which you can narrow down with `filter` blocks and order with `sort` blocks.

To allocate a floating IP, use the [`fptcloud_floating_ip`](../resources/floating_ip) resource. To
learn more, see [Floating IP](https://docs.fptcloud.com/docs/fpt-network/floating-ip/overview/) in
the FPT Cloud documentation.

## Example Usage

All examples look up the VPC by name with the [`fptcloud_vpc`](vpc) data source:

```terraform
data "fptcloud_vpc" "example" {
  name = "example-vpc"
}
```

### Look up a floating IP by address

Use this to get the ID of a floating IP when you know its public address. `one()` returns the single
matching floating IP.

```terraform
variable "public_address" {
  type        = string
  description = "A public IP address already allocated in the VPC."
}

data "fptcloud_floating_ip" "web" {
  vpc_id = data.fptcloud_vpc.example.id

  filter {
    key    = "ip_address"
    values = [var.public_address]
  }
}

output "web_floating_ip_id" {
  value = one(data.fptcloud_floating_ip.web.floating_ips).id
}
```

### Associate an existing floating IP with an instance

Use this when the floating IP was allocated outside your configuration, for example in the console,
and you want Terraform to connect it to an instance. This example uses the `public_address` variable
declared in the previous example.

```terraform
data "fptcloud_floating_ip" "web" {
  vpc_id = data.fptcloud_vpc.example.id

  filter {
    key    = "ip_address"
    values = [var.public_address]
  }
}

resource "fptcloud_floating_ip_association" "web" {
  vpc_id         = data.fptcloud_vpc.example.id
  floating_ip_id = one(data.fptcloud_floating_ip.web.floating_ips).id
  instance_id    = fptcloud_instance.web.id
}
```

The `fptcloud_instance.web` resource is not shown here; see
[`fptcloud_instance`](../resources/instance) for a complete instance definition.

### List the floating IPs that are not in use

Use this to find addresses that are allocated but not associated with any instance, oldest first.

```terraform
data "fptcloud_floating_ip" "free" {
  vpc_id = data.fptcloud_vpc.example.id

  filter {
    key    = "status"
    values = ["IN_ACTIVE"]
  }

  sort {
    key       = "created_at"
    direction = "asc"
  }
}

output "free_addresses" {
  value = [for fip in data.fptcloud_floating_ip.free.floating_ips : fip.ip_address]
}
```

## Argument Reference

The following arguments are supported:

* `vpc_id` - (Required) The ID of the VPC whose floating IPs you want to read. Use the `id` of the
  [`fptcloud_vpc`](vpc) data source.
* `filter` - (Optional) One or more `filter` blocks as defined below. A floating IP is returned only
  if it matches every `filter` block.
* `sort` - (Optional) One or more `sort` blocks as defined below. Blocks are applied in order.

### filter

* `key` - (Required) The floating IP attribute to filter on. Valid values are `id`, `ip_address`,
  `nat_type`, `status` and `created_at`.
* `values` - (Required) A list of values. A floating IP matches when its attribute matches at least
  one of the values (or all of them, see `all`).
* `match_by` - (Optional) How to compare the values. Valid values are `exact` (whole value,
  case-insensitive), `substring` (the value is contained in the attribute, case-sensitive) and `re`
  (the value is a regular expression). Defaults to `exact`.
* `all` - (Optional) Set to `true` to require the attribute to match all of the `values` instead of
  at least one. Defaults to `false`.

### sort

* `key` - (Required) The floating IP attribute to sort on. Valid values are `id`, `ip_address`,
  `nat_type`, `status` and `created_at`.
* `direction` - (Optional) The sort direction. Valid values are `asc` and `desc`. When omitted, the
  floating IPs are sorted in ascending order.

## Attribute Reference

In addition to all arguments above, the following attributes are exported:

* `id` - An identifier generated by Terraform for this lookup. It is not a floating IP ID.
* `floating_ips` - The list of floating IPs that match all `filter` blocks, in the order set by
  `sort`. Each element has the following attributes:
  * `id` - The ID of the floating IP. Pass it to the `floating_ip_id` argument of
    [`fptcloud_floating_ip_association`](../resources/floating_ip_association).
  * `ip_address` - The public IP address.
  * `status` - The status of the floating IP, for example `ACTIVE` when it is associated with an
    instance and `IN_ACTIVE` when it is not.
  * `nat_type` - The NAT type of the floating IP, as FPT Cloud reports it.
  * `created_at` - The time the floating IP was allocated.
  * `tag_ids` - The IDs of the tags attached to the floating IP.
  * `vpc_id` - Not filled in; it is always empty. Use the `vpc_id` argument instead.

## Results and errors

* If no floating IP matches your filters, `floating_ips` is an empty list and Terraform does not
  report an error. An expression such as `floating_ips[0].id` then fails. Use `one(...)` or check
  `length(...)` if the floating IP may be missing.
* If the VPC has no floating IPs at all, the data source fails with an error.
