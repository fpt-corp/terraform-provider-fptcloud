# Terraform Provider Fptcloud

Terraform provider for FPT Cloud. It manages compute, networking, storage, Kubernetes, database and backup resources through the FPT Cloud API.

User documentation for every resource and data source is in [docs/](docs/); example configurations are in [examples/](examples/).

## Requirements

- [Terraform](https://developer.hashicorp.com/terraform/downloads) >= 1.0
- [Go](https://golang.org/doc/install) >= 1.21 (CI uses Go 1.24. On macOS 15, test binaries built with Go 1.21 fail to load, so use Go 1.24 there as well.)
- [golangci-lint](https://golangci-lint.run/) v1.64.8, only for linting. `.golangci.yml` uses the v1 format, which golangci-lint v2 rejects.

## Build

```sh
go build ./...   # compile every package
go install .     # build the provider binary into $(go env GOPATH)/bin/terraform-provider-fptcloud
```

## Run the provider locally

Terraform normally downloads the provider from the registry. To make it use your local build instead, add a `dev_overrides` block to `~/.terraformrc`:

```hcl
provider_installation {
  dev_overrides {
    "registry.terraform.io/fpt-corp/fptcloud" = "/home/<you>/go/bin"   # output of: go env GOPATH, plus /bin
  }
  direct {}
}
```

Then, in any Terraform configuration that uses `source = "fpt-corp/fptcloud"`:

1. Run `go install .` in this repository after each code change.
2. Set credentials, either in the `provider "fptcloud"` block or as environment variables (see [Configuration](#configuration)).
3. Run `terraform plan` or `terraform apply`. Terraform prints a warning that development overrides are in effect and uses the local binary; `terraform init` is not needed for an overridden provider.

Remove the `dev_overrides` block to go back to the published provider.

### Debug with a debugger

`-debug` starts the provider as a long-running process that a debugger can attach to:

```sh
go run . -debug
```

The provider prints a `TF_REATTACH_PROVIDERS=...` line. Export it in the shell where you run Terraform, and Terraform talks to that process instead of starting its own. To use breakpoints, start the same command from your IDE's debugger (for example Delve via VS Code or GoLand).

## Configuration

The provider reads these settings from the `provider "fptcloud"` block or from environment variables. The variables are the ones the tests use.

| Provider argument | Environment variable | Required | Default or values |
|---|---|---|---|
| `token` | `FPTCLOUD_TOKEN` | yes | |
| `tenant_name` | `FPTCLOUD_TENANT_NAME` | yes | |
| `region` | `FPTCLOUD_REGION` | yes | `VN/HAN`, `VN/SGN` or `JP/JCSI2` |
| `api_endpoint` | `FPTCLOUD_API_URL` | no | `https://console-api.fptcloud.com/api` |
| `timeout` (minutes) | `FPTCLOUD_TIMEOUT` | no | `15` |

For the Japan region, set `api_endpoint` to `https://console-api.fptcloud.jp/api`. See [docs/index.md](docs/index.md) for full provider examples.

## Test

### Unit tests

Runs the tests that do not need an FPT Cloud account:

```sh
go test ./...
```

Acceptance tests (`TestAcc*`) are skipped in this mode because `TF_ACC` is not set.

### Acceptance tests

Acceptance tests create and read real resources in FPT Cloud, so they need an account and may incur cost. `make testacc` sets `TF_ACC=1` and runs every test with a 120-minute timeout:

```sh
export FPTCLOUD_TOKEN=your_token
export FPTCLOUD_TENANT_NAME=your_tenant_name
export FPTCLOUD_REGION=your_region
export FPTCLOUD_API_URL=your_api_url    # optional
export VPC_ID=your_vpc_id
export INSTANCE_ID=your_instance_id     # only for TestAccFptCloudSnapshot_basic

make testacc                                          # all tests
make testacc TESTARGS='-run=TestAccFptCloudInstances_basic'  # one test
```

`make` with no target also runs `testacc`. A `TestAcc*` test whose variables are unset is skipped rather than failed, which is how CI runs the suite without credentials. `TestAccFptCloudInstances_basic` expects `VPC_ID` to contain at least one instance.

### Lint

CI runs these checks on every push (see [.github/workflows/test.yml](.github/workflows/test.yml)):

```sh
golangci-lint run --timeout=3m
go vet ./...
```

## Documentation

[docs/](docs/) was generated by [tfplugindocs](https://github.com/hashicorp/terraform-plugin-docs) from the provider schema and [examples/](examples/). To regenerate it:

```sh
go generate ./...
```

Regenerating can overwrite text that was edited directly in `docs/`, so review `git diff docs/` before committing and keep only the intended changes.

## Release

Pushing a tag that matches `v*` (for example `v0.1.0`) runs [.github/workflows/release.yml](.github/workflows/release.yml), which builds and signs the release with GoReleaser using [.goreleaser.yml](.goreleaser.yml).
